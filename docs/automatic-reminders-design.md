# 自动提醒：功能设计

状态：设计提案；本次交付界面原型与实现规格，尚未接入应用。

## 目标与入口

让用户在开始使用电脑时收到自定义提醒，并可同时执行自定义终端命令。例如每天首次使用电脑时提醒「先确定今天最重要的三件事」，同时打开工作目录或启动脚本。

设置首页新增「自动提醒」卡片，摘要为「已启用 N 条规则」。独立页面提供总开关、规则列表、新建、编辑、复制、删除和最近执行结果。现有「解锁问候」保持为独立设置；同一次事件中，自定义提醒优先于普通问候。

## 规则编辑

| 字段 | 默认值与行为 |
| --- | --- |
| 名称 | 必填；用于列表和提醒标题 |
| 启用 | 新建保存后启用；总开关默认关闭，首次保存时明确允许开启 |
| 触发时机 | 开始使用电脑（登录 / 解锁；无需解锁的睡眠唤醒也计入） |
| 频率 | 每天首次；可选每次 |
| 动作 | 仅显示提醒 / 仅运行命令 / 提醒并运行命令 |
| 提醒内容 | 支持多行纯文本；有提醒动作时必填 |
| 命令 | 支持多行脚本；有命令动作时必填 |
| 工作目录 | 默认当前用户主目录；支持路径输入或目录选择器 |
| 命令超时 | 默认 60 秒；高级选项支持 10–600 秒 |
| 启动延迟 | 默认 3 秒；高级选项支持 0–60 秒 |

编辑表单显式保存，取消不改变已保存规则。没有启用任何规则时显示「添加第一条提醒」，避免空仪表盘。命令区域采用等宽字体，并说明「按当前用户权限在后台运行，不打开终端窗口」。

「预览提醒」只展示内容，不运行命令、不消耗当天次数。「试运行命令」单独操作，运行当前草稿并展示真实输出；同样不消耗自动触发次数。原型中的预览只模拟提醒，不执行电脑上的命令。

## “打开电脑”的明确含义

产品文案使用「开始使用电脑」，避免把开盖、开机、唤醒混为一谈。

首版提供三种触发时机：

1. **开始使用电脑（推荐）**：当前用户登录 / 解锁，或睡眠唤醒后直接回到可用桌面。同一次唤醒加解锁只算一次。
2. **从睡眠唤醒**：包括开盖导致的唤醒；如果仍处于锁屏则等到解锁后执行。关闭屏幕后点亮屏幕、单纯开盖但未唤醒不算。
3. **灵动岛启动时**：每次启动应用触发，按所选频率去重。

登录时自动启动的应用可以补发一次「开始使用电脑」事件；普通手动重启应用不视为登录或开始使用电脑。需要区分登录启动来源，无法可靠识别时只能使用真实系统事件，不猜测、不补跑命令。

应用退出期间不监听、不补发历史事件。页面显示登录时启动状态，提供显式开启入口；不能在保存提醒时悄悄注册登录项。

## 触发与去重

- 所有原始通知先进入 `ComputerUseEventMonitor`，统一生成规范事件 `ComputerUseEvent(id, kind, date, sessionID)`。
- 一次睡眠、唤醒、解锁链路归为同一个 session。进程内同源通知使用单调时间合并 5 秒内的重复事件；不能只靠 5 秒去重，因为解锁可能晚于唤醒数分钟。
- 只在当前用户会话可用时执行。不因网络后台唤醒、显示器独立唤醒、切换其他用户或重复系统通知自动跑命令。
- 「每天首次」按**每条规则**判断该规则当日首次匹配的事件。使用本地公历日期，例如 `2026-10-14`；同时持久化已触发日期集合，防止跨时区或调整时钟后返回已运行日期又执行一次。
- 每天规则在启动动作前先持久化 `claimed` 记录。当日命令失败、超时、应用意外退出、编辑规则或关闭再启用，都不自动重跑。恢复后将未完成记录标记为「结果未知」；允许手动重试。
- 「每次」规则按规范事件 ID 去重；记录执行中状态，同一规则正在运行时跳过新事件并写入「已跳过：上次仍在运行」。跨规则命令串行调度，防止唤醒时大量进程同时启动。
- 新建 / 编辑 / 启用规则不会立刻触发，不补跑今天过去的事件。首个未来事件正常匹配；复制规则视为新规则，并在界面明确其独立频率。
- 启动延迟内再次锁屏则等待下次解锁；如果规则或总开关关闭，取消待执行动作。已启动的命令不会因关闭开关被突然杀掉；通过执行详情「停止」主动终止。
- 队列消费前再次检查规则启用状态与本地日期。跨午夜时，对仍有效的「开始使用电脑」使用实际派发日期占用一次；不补发昨日任务。

## 提醒与执行结果

灵动岛展开显示规则名称、提醒文本和关闭按钮。若含命令，则附「正在运行 / 已完成 / 失败 / 超时」及「查看结果」。提醒与命令是同一次事件的独立动作：内容立即进入展示队列，不等待命令完成。

默认展示 12 秒，悬停时暂停自动收起；关闭提醒不会停止命令。长内容在展开详情中查看全文。多条提醒进入队列，合并显示「还有 N 条」而不是抢占彼此；计时器 / 番茄钟到时提醒先展示，之后显示自定义提醒。普通解锁问候在有自定义提醒时跳过。

只运行命令时，成功不弹提醒；失败显示简短通知并提供结果入口。关闭灵动岛可见性时，设置页显示未读提醒与结果；不会因为隐藏窗口导致命令停止。

首版不添加「稍后提醒」，避免它和自动命令重复执行语义混杂。后续可加入只重放文字、绝不重跑命令的稍后提醒。

## 命令运行规格

- 使用异步 `Process` 启动 `/bin/zsh`，参数 `-l -c` 加完整脚本文本，避免手工拼接引号；工作目录通过进程属性设置，不能拼进 `cd ...`。
- 命令输入完整保留，不执行模板展开或后台改写。默认继承应用进程环境并加载登录 shell 环境，工作目录展开用户主目录。交互式 shell 配置可能与 Terminal 不同，结果页提供实际 shell 和目录。
- stdin 默认关闭，不支持密码 / 交互提示。需要长期运行的服务应由脚本转交给服务管理器；该功能用于有明确完成状态的短任务。
- 持续并行读取 stdout / stderr，不能等待进程结束后再读以免管道阻塞；输出在内存与历史文件中均有上限，默认合计 64 KiB，截断显式标记。
- 结果保存退出码、开始 / 结束时间、输出摘要及失败原因。超时先终止进程组，再在短暂宽限后强制结束受管子进程；不要只结束 shell 造成子进程残留。
- 不自动提权，不替用户授予系统权限。首次配置命令时用一句解释说明自动执行含义；保存和启用即授权按规则执行，无需每次弹确认。
- 命令与历史留在本机，不写到 analytics 或统一系统日志。历史默认保留最近 100 条，可清空；规则和用于防重复的触发账本独立保存，清空展示历史不会重置每日次数。
- 若进程崩溃后无法确认命令是否产生副作用，显示「结果未知」，不承诺严格 exactly-once；策略是持久化抢占后的自动执行至多一次，重试由用户决定。

## 数据与现有代码接入

建议新增组件：

| 组件 | 职责 |
| --- | --- |
| `ReminderRule.swift` | Codable 规则、触发时机、频率、动作配置与校验 |
| `ReminderStore.swift` | @MainActor ObservableObject；规则、总开关、持久化迁移 |
| `ReminderTriggerLedger.swift` | 事件 ID、每日日期账本、claimed / finished / unknown |
| `ComputerUseEventMonitor.swift` | 用户会话、睡眠、唤醒、解锁和启动来源归一化 |
| `ReminderCoordinator.swift` | 规则匹配、延迟、去重、命令调度、提醒派发 |
| `ReminderCommandRunner.swift` | 异步进程管理、并发管道读取、超时与取消 |
| `ReminderPresentation.swift` | 提醒 / 执行状态；与计时完成和问候统一排队 |
| `ReminderSettingsView.swift` | 规则管理、编辑、预览与执行结果 |

`IslandSettingsHomeView.swift` 的 `IslandSettingsPage` 增加 `.reminders`，首页增加入口；`DynamicIslandApp.swift` 的 AppDelegate 负责启动 / 停止协调器，把现有解锁监听统一交给事件监视器；`IslandModel.swift` 增加自定义提醒展示状态；`ContentView.swift` 的 alert overlay 增加提醒卡片；可在菜单栏加入「自动提醒…」快捷入口。

目前 `AppDelegate` 使用 `IslandSessionMonitor` 统一监听会话、睡眠和屏幕锁定／解锁通知，并定期核对实际会话状态。未来事件监视器应复用这些检查。不能把会话激活等同于屏幕解锁：Apple 文档定义前者为用户会话切入。字符串形式的解锁通知仍需在目标 macOS 版本上验证，不能承诺仅靠公开会话激活通知覆盖所有锁屏解锁。

唤醒可观察 `NSWorkspace.didWakeNotification`，但它本身只表达睡眠唤醒，不能直接证明用户已开始使用电脑。登录时启动建议使用 `SMAppService.mainApp` 并展示服务真实状态；系统拒绝或要求用户操作时反馈到页面。

Apple 参考：[会话激活通知](https://developer.apple.com/documentation/appkit/nsworkspace/sessiondidbecomeactivenotification)、[SMAppService](https://developer.apple.com/documentation/servicemanagement/smappservice)、[主应用登录项](https://developer.apple.com/documentation/servicemanagement/smappservice/mainapp)。

## 首版范围与验收

首版实现规则管理、三种事件时机 × 两种频率、三种动作、自定义文本 / 命令 / 工作目录、提醒队列、执行结果、登录时启动入口。不引入云同步、Cron、联网条件、任意日历定时或复杂动作链；现有定时闹钟继续负责指定时间提醒。

关键验收用可注入时钟 / 事件源 / 命令执行器覆盖：

1. 睡眠唤醒后解锁只触发一次；解锁在十分钟后仍不重跑。
2. 同日解锁多次，「每次」多次触发，「每天首次」一次；下一自然日才重新允许。
3. 每日账本跨应用重启保留；返回先前已运行日期不重复；从当日第二次使用才启用的新规则等待下次事件。
4. 普通手动重启只匹配「应用启动」，不误匹配「开始使用电脑」。
5. 空文字、空命令、不可访问目录有对应校验；提醒预览不执行命令。
6. 命令正常结束、非零退出、大量 stdout / stderr、超时、用户停止均给出正确结果且不阻塞界面。
7. 失败和崩溃不自动重试；关闭再启用 / 编辑同一条每日规则不重置当日次数。
8. 多规则、计时到时和解锁问候同时发生时，提醒不丢失、不反复切换；命令不随展示卡片消失而结束。
9. 应用未运行、无用户的后台唤醒、其他用户会话和延迟内禁用均不自动执行。
10. 命令只按启用规则自动运行；取消编辑、保存关闭状态或仅点击预览都不执行。
